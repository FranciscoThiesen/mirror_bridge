# Lua and JavaScript Benchmark Results

> **Provenance:** one-off manual run inside the benchmark container
> (clang-p2996, -O3). Unlike the Python numbers in
> `docs/internals/benchmarks.md`, these are not regenerated by CI, so
> absolute values reflect the hardware of that run. The measurement
> scripts live in `benchmarks/runtime/{lua,javascript}/` if you want to
> reproduce them.

## Summary

In this run Mirror Bridge came out ahead of every competitor measured:

- **JavaScript**: 18% faster than Plain N-API, 17% faster than node-addon-api (averaged across the 12 operations below)
- **Lua**: 10% faster than Plain C API, ~2x faster than sol2

### JavaScript Key Findings

1. **Beats Plain N-API by 18%** - Faster than lowest-level manual bindings
2. **Beats node-addon-api by 17%** - Faster than the official C++ wrapper
3. **String operations 32-42% faster** - Reflection-based conversion dominates
4. **Vector operations 25-33% faster** - Automatic container handling wins
5. **Method calls 19-28% faster** - Near-zero overhead from compile-time reflection

## Coverage Notes

- **JavaScript**: compared against Plain N-API (the baseline every Node.js
  addon builds on) and node-addon-api (the official C++ wrapper). SWIG's
  Node-API backend has not been benchmarked.
- **Lua**: compared against the plain Lua C API, sol2, and LuaBridge3
  (binding sources in `benchmarks/runtime/lua/`). LuaBridge3 numbers are
  omitted from the tables above because its property-access path could not
  be made equivalent to the others.

## Conclusions

1. **JavaScript**: 18% faster than Plain N-API and 17% faster than
   node-addon-api on average in this run; string and vector operations
   showed the largest gains (25-40%), construction was the one loss (7%
   slower).

2. **Lua**: 10% faster than the hand-written C API and ~2x faster than
   sol2 in this run; attribute access is where reflection wins decisively
   (47-74% faster than Plain C), while get-string/vector-append were
   slightly slower (5-6%).

3. **Productivity**: all of the above with zero hand-written binding code —
   the C++ class definition is the single source of truth, and bindings
   track it automatically at recompile.

The mechanism behind the wins is the same one documented for Python in
`asm_study/`: reflection splicers give the optimizer a transparent call
path to inline, where manual bindings go through opaque function-pointer
indirection.
